# SYS-096 — Keep apps launched from Noctalia out of noctalia.service's cgroup

Helium (PID 5893, 0.21.1.1) aborted with SIGTRAP at 2026-11-09 13:47:57 CET
during the `test` activation of d6cfd29, which restarted `noctalia.service`.
The core's stack buffer holds the fatal log line:
`FATAL:content/browser/gpu/gpu_data_manager_impl_private.cc:385] GPU process
isn't usable. Goodbye.` The core's heap holds the GPU log message "The GPU process
failed to start!" three times in a row.

Cause: Noctalia started that Helium directly as its child, so Helium was in
`noctalia.service`'s cgroup. Chromium's `StartTransientUnit` moves only the
browser PID into `app-org.chromium.Chromium-<pid>.scope`. The zygotes and the
GPU process, forked before that move, stayed in `noctalia.service`. Stopping
Noctalia (`KillMode=control-group`) killed them. Every GPU relaunch then failed,
fallback modes ran out, and Chromium crashed itself on purpose. Evidence:

- `noctalia.service` reported a 6G memory peak on 2026-11-09, against 693M on
  2026-11-07, because Helium's children were counted in it.
- Helium 0.21.1.1 started from Vicinae on 2026-11-07 (`systemd-run gio launch
  helium.desktop`, its own unit) survived Noctalia stopping at 21:49 that day.
- oo7's "Client :1.15 disconnected" at 13:47:57.47 is Noctalia's own Secret
  Service session. The same line appeared when Noctalia stopped on 2026-11-07.
  It is not Helium's libsecret session, and D-Bus, libsecret and the theme
  policy are not involved.

Every app started from Noctalia's launcher, dock or bar is exposed in the same
way. Any activation that changes the Noctalia package (for example the pending
`switch` in [SYS-095](SYS-095.md)) restarts the service and kills those apps.

Fix (live since 2026-11-09 19:08, see the
[changelog](../SYSTEM_CHANGELOG.md#noctalia-launches-apps-as-systemd-services--2026-11-09)): set `launch_apps_as_systemd_services = true`
in `[shell]` of `home/noctalia/config.toml`. Noctalia then runs each app with
`systemd-run --user --slice=app.slice --unit=app-…@….service`. Noctalia
already runs as a systemd user service, which the option requires. Apps
launched before the change stay in `noctalia.service` until they are restarted.

Done when: the option is active, a Helium started from Noctalia is in its own
`app-…` unit (none of its processes are listed under
`systemctl --user status noctalia.service`), and restarting `noctalia.service`
leaves that Helium running.
