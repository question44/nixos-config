# SYS-098 — Helium web-app launchers: write a stable Exec path instead of the versioned store path

Asked by the user on 2026-11-11. Helium writes each installed web app's
launcher (`~/.local/share/applications/chrome-<app-id>-Default.desktop`) with
`Exec=/nix/store/<hash>-helium-<version>/opt/helium/helium-wrapper …`. After a
Helium update and a garbage collection that path no longer exists and the web
app stops launching. This happened on 2026-11-11: the three launchers
("ChatGPT", "T3 Code", "erebor services") pointed at Helium 0.19.2.1 and
0.20.2.1, which that day's cleanup removed. They were repaired by hand to
`Exec=/run/current-system/sw/bin/helium --profile-directory=Default --app-id=…`
(not yet launched to confirm). Helium rewrites the path whenever it creates or
refreshes a shortcut, so the hand fix does not last.

Cause: Chromium writes `CHROME_WRAPPER` into shortcuts. Helium's
`opt/helium/helium-wrapper` (0.21.1.1) sets it unconditionally on lines 11–14
(`CHROME_WRAPPER="$(readlink -f "$0")"`, then
`HERE="$(dirname "$CHROME_WRAPPER")"`, `export CHROME_WRAPPER`), so a variable
set from outside is overwritten, and `HERE` depends on the store path.

Plan: override the Helium package used by `programs.helium`
(`modules/workstation/session.nix`, module from the `helium` flake input;
check whether it exposes a `package` option) and patch the wrapper so `HERE`
still comes from `readlink -f "$0"` while `CHROME_WRAPPER` is
`/run/current-system/sw/bin/helium`. The package repackages a prebuilt
binary, so the override should only re-run the wrapper/fixup, not compile
Chromium: confirm with `scripts/erebor-diff` before activating.

Done when: activated; after the switch, `CHROME_WRAPPER` in a running
Helium's environment (`/proc/<pid>/environ`) is
`/run/current-system/sw/bin/helium`; a web app installed or reinstalled from
Helium gets `Exec=/run/current-system/sw/bin/helium …`; and the three existing
web apps start from the launcher.
