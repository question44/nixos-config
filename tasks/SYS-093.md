# SYS-093 — macOS JetBrains shortcuts in Zed

On 2026-11-08 the user asked to use the macOS JetBrains keymap in Zed on erebor.
Start only after [SYS-081](SYS-081.md) (the dendritic migration) has landed. That
migration rewrites the Home Manager and xremap modules this task touches.

Today `~/.config/zed/settings.json` is an unmanaged file containing
`"base_keymap": "JetBrains"`. On Linux, Zed loads the Ctrl-based variant of that
keymap. The user chose **Super** as Cmd, matching the key's position on the Mac.

Plan:
- Generate a Zed `keymap.json` from Zed's `assets/keymaps/macos/jetbrains.json`
  and the `default-macos.json` bindings it builds on (pinned to the packaged
  `zed-editor` version), with `cmd-` rewritten to `super-`. Deploy it through
  Home Manager from `modules/home/` (Linux only). `settings.json` stays
  user-editable.
- List the Super combinations that Umbriel (and xremap's Caps layer) grab. For
  each clash, decide whether Zed gets the key while it is focused or whether the
  desktop keeps it, and ask the user about the clashes that matter (Cmd+W/Q/Tab,
  etc.).
- Keep the Ctrl-based Linux bindings that are not overridden, so terminal Ctrl-C
  and similar shortcuts still work.

Done when: Super+Shift+O, Super+E, Super+B, Super+/, Super+D and Super+W behave as
the same Cmd shortcuts do in the macOS JetBrains keymap inside Zed, the desktop's
Super shortcuts still work outside Zed, and the change is activated, recorded
and committed.

Progress 2026-11-08: implemented and activated (generation 322, see the
changelog). Super+0 stays with Umbriel; 56 other Umbriel Super binds removed.
Remaining: the user confirms the Done-when shortcuts in Zed with the real
keyboard, then close with `scripts/erebor-tasks close SYS-093 DONE`.
